# DDL conventions

How SCHEMA-DESIGN.md becomes files in this project. Where the design is explicit, the design
wins; this file fixes only what the design leaves to implementation, and says so.

## Files

- Project-level objects (schemas, database roles, filegroups) live in `Database/` and `Storage/`; every
  other folder is a schema name in lower case (`security/`, not `Security/` — the generator's stale
  check compares paths case-sensitively).
- One table per file: `<schema>/Tables/<Table>.sql`, containing the table, its indexes, its
  `PnC.TemporalClass` extended property, and nothing else. Registry tables
  (`<Entity>Registry`, decision 67) are their own file.
- Hand-written views, functions and procedures: `<schema>/Views|Functions|Procedures/<Name>.sql`.
- **Generated** objects (views and base write procedures, decision 69 / §0.5) are emitted by
  `tools/generate.py` into the same folders with a first-line header
  `-- GENERATED by tools/generate.py … do not edit`. `tools/check_generated.py` fails the build
  step if a generated file is stale or has been edited.
- Seeds: `PostDeploy/Seed_<schema>_<Table>.sql`, idempotent `MERGE`, included in step order from
  `PostDeploy/PostDeploy.sql`. Only lists the design states literally are seeded; predecessor
  lists are migration (§14.2).
- `STEPS.md` maps each design step to its files and lists every column whose type was
  defaulted by the rules below. `PROCEDURES.md` lists the domain-rule procedures the design
  names that are **not** built in this pass.

## Temporal classes (§0.3, decisions 67–73)

Every table carries `PnC.TemporalClass`. The column block per class:

| Class | Identity | Valid time | System versioning | Audit block | Delete |
|---|---|---|---|---|---|
| `ValidTime` | `RowSeq`, `RowId`, `EntityId` → registry | `ValidFrom`, `ValidTo`, `ValidFromQuality` | yes, hidden `SysStart`/`SysEnd`, `<Table>_History` | yes | soft |
| `BiTemporal` | same | same | same | yes | soft |
| `Versioned` | `RowSeq`, `RowId`, `EntityId` (own or parent per design) | none (version number / effective period are domain columns) | yes | yes | soft |
| `Reference` | natural key PK as the design names it | none | yes | yes | `IsActive` (design) — no `IsDeleted` |
| `AppendOnly` | design's own id | none | **no** | only what the design lists | none |
| `Subclass` | the parent's `RowId` as PK and FK (revision subclasses `ConfigurationFile`, `Study`, `Rationale`, `Drawing`) | the parent's | yes | yes | soft |
| `FileTable` | FILESTREAM FileTable (`document.FileStore`) | none | **no** (not possible) | none | none |

Audit block = `CreatedBy`, `CreatedAt`, `ModifiedBy`, `ModifiedAt`, `IsDeleted`, `DeletedBy`,
`DeletedAt`, `MigrationRunId`. `CreatedBy` / `ModifiedBy` / `DeletedBy` → `personnel.Actor`.
Registry tables are not versioned (identity only) and carry class `Registry`, which the generator skips.
Every `ValidTime` / `BiTemporal` / `Versioned` table has its own `<Table>Registry` unless it is an
extension sharing a parent's identity (then `EntityId` references the parent's registry and the
generated `_Add` takes `@EntityId` as input instead of creating one).

Canonical block for `ValidTime` / `BiTemporal` (copy verbatim; keep column order):

```sql
    [RowSeq]            BIGINT IDENTITY(1,1) NOT NULL,
    [RowId]             UNIQUEIDENTIFIER  NOT NULL CONSTRAINT [DF_<T>_RowId] DEFAULT NEWSEQUENTIALID(),
    [EntityId]          UNIQUEIDENTIFIER  NOT NULL CONSTRAINT [FK_<T>_Registry] REFERENCES [<s>].[<E>Registry] ([EntityId]),
    [ValidFrom]         DATETIMEOFFSET(7) NOT NULL,
    [ValidTo]           DATETIMEOFFSET(7) NULL,
    [ValidFromQuality]  TINYINT           NOT NULL CONSTRAINT [DF_<T>_ValidFromQuality] DEFAULT 0,
    [SysStart]          DATETIME2(7) GENERATED ALWAYS AS ROW START HIDDEN NOT NULL,
    [SysEnd]            DATETIME2(7) GENERATED ALWAYS AS ROW END   HIDDEN NOT NULL,
    PERIOD FOR SYSTEM_TIME ([SysStart], [SysEnd]),
    [CreatedBy]         UNIQUEIDENTIFIER  NOT NULL CONSTRAINT [FK_<T>_CreatedBy]  REFERENCES [personnel].[Actor] ([ActorId]),
    [CreatedAt]         DATETIMEOFFSET(7) NOT NULL,
    [ModifiedBy]        UNIQUEIDENTIFIER  NOT NULL CONSTRAINT [FK_<T>_ModifiedBy] REFERENCES [personnel].[Actor] ([ActorId]),
    [ModifiedAt]        DATETIMEOFFSET(7) NOT NULL,
    [IsDeleted]         BIT               NOT NULL CONSTRAINT [DF_<T>_IsDeleted] DEFAULT 0,
    [DeletedBy]         UNIQUEIDENTIFIER  NULL     CONSTRAINT [FK_<T>_DeletedBy]  REFERENCES [personnel].[Actor] ([ActorId]),
    [DeletedAt]         DATETIMEOFFSET(7) NULL,
    [MigrationRunId]    UNIQUEIDENTIFIER  NULL     CONSTRAINT [FK_<T>_MigrationRun] REFERENCES [migration].[Run] ([RunId]),
    -- domain columns follow
    CONSTRAINT [PK_<T>] PRIMARY KEY CLUSTERED ([RowSeq]),
    CONSTRAINT [UQ_<T>_RowId] UNIQUE NONCLUSTERED ([RowId])
) WITH (SYSTEM_VERSIONING = ON (HISTORY_TABLE = [<s>].[<T>_History]));
GO
CREATE INDEX [IX_<T>_Entity] ON [<s>].[<T>] ([EntityId], [ValidFrom]);
GO
EXEC sys.sp_addextendedproperty @name = N'PnC.TemporalClass', @value = N'ValidTime',
    @level0type = N'SCHEMA', @level0name = N'<s>', @level1type = N'TABLE', @level1name = N'<T>';
GO
```

`Versioned` = the same without the three valid-time columns. `Reference` = natural key PK,
then `SysStart`/`SysEnd`/`PERIOD`, `CreatedBy`, `CreatedAt`, `ModifiedBy`, `ModifiedAt`,
`IsActive BIT NOT NULL DEFAULT 1`, `MigrationRunId`, system versioning on.

Extension tables sharing the parent's `EntityId` (`device.Device`, `record.Instrument`,
revision subclasses keyed by `RowId`): the shared id is the PK and an FK to the parent; they
keep their own class block otherwise.

## Naming (§0.2)

Singular PascalCase tables and columns. `<Role>EntityId` for a reference to a thing,
`<Role>RowId` for a reference to a fact version. `…Code` for codes. Constraints:
`PK_`, `UQ_`, `UX_` (unique index), `IX_`, `FK_<Table>_<Role>`, `CK_<Table>_<Rule>`,
`DF_<Table>_<Column>`. History tables `<Table>_History`.

## Types where the design gives none

Applied uniformly and listed per column in `STEPS.md`:

| Design wording | Type |
|---|---|
| code, kind, status, role, category | `NVARCHAR(40)`; status/kind with a listed value set also gets a `CHECK` |
| key, label, designator, reference, number (textual) | `NVARCHAR(100)` |
| name, title, summary line | `NVARCHAR(200)` |
| short free text (reason, basis, description ≤ a paragraph) | `NVARCHAR(400)` |
| description, notes, detail, text, JSON payload | `NVARCHAR(MAX)` |
| instant | `DATETIMEOFFSET(7)` (decision 73) |
| calendar date the design names as a date | `DATE` |
| measure without a stated precision | `DECIMAL(18,4)` |
| count | `INT` |
| flag | `BIT NOT NULL DEFAULT 0` (default 1 only where the design says the normal case is true) |
| hash | `BINARY(32)` |
| GUID | `UNIQUEIDENTIFIER` |

`TimeSourceQuality` is `TINYINT` with a `CHECK` on 0–4: 0 GPS-locked, 1 NTP, 2 relay clock
unverified, 3 manual entry, 4 migrated-unknown (order as listed in §0.3).

## Polymorphic references

`SubjectKind` / `SubjectEntityId` (and `FromKind`, `MemberKind`, `ScopeKind`, `GranteeKind`…)
are not foreign keys. The kind column carries a `CHECK` over the design's list; `ref.SubjectKind`
maps each kind to the registry table that holds it; `meta.fEntityExists(@kind, @entityId)`
validates in procedures. A polymorphic reference the design says "the procedure enforces" is
never made an FK.

## Generated objects (decision 69, §0.5)

From the deployed catalog, per table, by class:

| Class | Views | Procedures |
|---|---|---|
| `ValidTime` | `v<T>` (current), `v<T>History` | `<T>_Add`, `<T>_Revise`, `<T>_SoftDelete` |
| `BiTemporal` | `v<T>`, `v<T>History`, `f<T>AsOf(@validAt, @believedAt)` | same |
| `Versioned` | `v<T>`, `v<T>History` | `<T>_Add`, `<T>_Update`, `<T>_SoftDelete` |
| `Reference` | `v<T>` (active), `v<T>History` | `<T>_Upsert`, `<T>_Deactivate` |
| `AppendOnly` | `v<T>` (pass-through) | `<T>_Append` |
| `Subclass` | `v<T>`, `v<T>History` | `<T>_Add` (caller supplies the parent `RowId`), `<T>_Update`, `<T>_SoftDelete`, all keyed by that `RowId` |
| `FileTable` | `v<T>` (pass-through) | none: files arrive through the FILESTREAM share or the streaming API |

Current view: latest `ValidFrom` per `EntityId` with `ValidTo IS NULL`, `IsDeleted = 0`.
Every generated view carries `GRANT SELECT … TO [app_execute]`; every generated procedure
resolves the actor with `personnel.ResolveActor` unless `@actorId` is supplied (migration and
system callers), stamps the audit block, closes the prior row on `_Revise`, and sets
`IsDeleted` on `_SoftDelete`. No procedure deletes a row.

Hand-written procedures are verb-first (`config.ApproveDefinitionVersion`,
`asset.PlaceAsset`) so they never collide with generated `<Table>_<Verb>` names.

## Implementation choices recorded here (design left them open)

- `RowId` = `NEWSEQUENTIALID()` default (§1.6).
- Reference tables: `IsActive` instead of `IsDeleted`, per the design's own column lists.
- History tables live on the same filegroup as their table; `event.*` on `EventData` with
  indexes on `EventIndex`; `document.FileStore` on `BulkFiles`/FILESTREAM.
- The System actor for seeds and migrations is a fixed row:
  `ActorId = 00000000-0000-0000-0000-000000000001`, `SystemName = 'Platform.Seed'`.
